# Coxswain MCP tools

Generated by `coxswain_mcp --tools`; do not edit by hand.

## `task_create`

Create a task (status open) with an optional integer priority (default 0; higher is more important), optionally in a project (which must exist) and a milestone of that project. blocked_by lists ids of tasks that must be done before it can be claimed. Returns the new task.

Input schema: `{"type":"object","properties":{"title":{"type":"string"},"description":{"type":"string"},"blocked_by":{"type":"array","items":{"type":"integer"}},"priority":{"type":"integer"},"project":{"type":"string"},"milestone":{"type":"string"},"agent":{"type":"string"}},"required":["title"]}`

## `task_list`

List tasks, optionally only those with a status (open, claimed, done, cancelled), an assignee, a project or a milestone (milestone needs project). Each task is shown in full; blocked is true while a task it waits on is not done. Ordered by id, or with sort "priority" by priority (highest first, then id).

Input schema: `{"type":"object","properties":{"status":{"type":"string","enum":["open","claimed","done","cancelled"]},"assignee":{"type":"string"},"project":{"type":"string"},"milestone":{"type":"string"},"sort":{"type":"string","enum":["id","priority"]}}}`

## `task_next`

Show the next claimable task: the open task that no unfinished task blocks with the highest priority (lowest id among equals), optionally within a project or milestone (milestone needs project). With claim true it is also claimed for the agent (defaults to the server's --agent name), atomically. Says so, without failing, when nothing is claimable.

Input schema: `{"type":"object","properties":{"project":{"type":"string"},"milestone":{"type":"string"},"claim":{"type":"boolean"},"agent":{"type":"string"}}}`

## `task_history`

Show a task's history, oldest first: when (unix seconds), who, what happened (created, claimed, released, completed, noted, updated, moved) and a detail. Tasks from before the log existed start with whatever happened after.

Input schema: `{"type":"object","properties":{"id":{"type":"integer"}},"required":["id"]}`

## `task_update`

Change a task's title, description and/or priority (give at least one; the title cannot be empty, the description can; higher priority is more important). Anyone may edit any task, in any status. Status, assignee, project and milestone have their own tools. agent (else the server's --agent) is refreshed as a heartbeat if registered. agent (else the server's --agent) is refreshed as a heartbeat if registered.

Input schema: `{"type":"object","properties":{"id":{"type":"integer"},"title":{"type":"string"},"description":{"type":"string"},"priority":{"type":"integer"},"agent":{"type":"string"}},"required":["id"]}`

## `task_move`

Put a task in a project and optionally one of its milestones, or take it out. Giving project replaces the placement (the milestone is cleared unless given too); giving only milestone keeps the task's project. An empty string clears: project "" removes it from its project and milestone, milestone "" removes it from its milestone.

Input schema: `{"type":"object","properties":{"id":{"type":"integer"},"project":{"type":"string"},"milestone":{"type":"string"},"agent":{"type":"string"}},"required":["id"]}`

## `task_get`

Show one task by id, with its notes.

Input schema: `{"type":"object","properties":{"id":{"type":"integer"}},"required":["id"]}`

## `task_claim`

Claim an open task for an agent, atomically: if another agent got there first, or the task is blocked by unfinished tasks, it is refused. agent defaults to the server's --agent name.

Input schema: `{"type":"object","properties":{"id":{"type":"integer"},"agent":{"type":"string"}},"required":["id"]}`

## `task_release`

Give a claimed task back (status open). Only its assignee may release it unless force is true.

Input schema: `{"type":"object","properties":{"id":{"type":"integer"},"agent":{"type":"string"},"force":{"type":"boolean"}},"required":["id"]}`

## `task_complete`

Mark a claimed task done. Only its assignee may complete it unless force is true. An optional note is added.

Input schema: `{"type":"object","properties":{"id":{"type":"integer"},"agent":{"type":"string"},"note":{"type":"string"},"force":{"type":"boolean"}},"required":["id"]}`

## `task_note`

Append a note to a task (a handoff, a finding, a question). Anyone may add one.

Input schema: `{"type":"object","properties":{"id":{"type":"integer"},"text":{"type":"string"},"agent":{"type":"string"}},"required":["id","text"]}`

## `task_block`

Make a task wait for other tasks: adds the ids in blocked_by to its dependencies (ones it already has are kept once). Refuses unknown ids, the task itself, any dependency cycle, and a task that is done or cancelled. Cancelled tasks do not block.

Input schema: `{"type":"object","properties":{"id":{"type":"integer"},"blocked_by":{"type":"array","items":{"type":"integer"}},"agent":{"type":"string"}},"required":["id","blocked_by"]}`

## `task_unblock`

Stop a task waiting for other tasks: removes the ids in blocked_by from its dependencies. Refuses an id the task does not depend on.

Input schema: `{"type":"object","properties":{"id":{"type":"integer"},"blocked_by":{"type":"array","items":{"type":"integer"}},"agent":{"type":"string"}},"required":["id","blocked_by"]}`

## `task_cancel`

Drop a task that will not be done (status cancelled). Tasks are never deleted, so ids, history and notes stay. A cancelled task no longer blocks the tasks waiting on it. An open task may be cancelled by anyone; a claimed one only by its assignee unless force is true. An optional note says why.

Input schema: `{"type":"object","properties":{"id":{"type":"integer"},"agent":{"type":"string"},"note":{"type":"string"},"force":{"type":"boolean"}},"required":["id"]}`

## `task_reopen`

Put a done or cancelled task back to open, unassigned, so it can be claimed again. Tasks waiting on it are blocked again if it was done. An optional note says why.

Input schema: `{"type":"object","properties":{"id":{"type":"integer"},"agent":{"type":"string"},"note":{"type":"string"}},"required":["id"]}`

## `agent_register`

Announce this session as an agent (name from agent, else the server's --agent) with an optional line about what it is doing. Registering again just refreshes it. Call agent_heartbeat now and then so others can tell you are alive.

Input schema: `{"type":"object","properties":{"agent":{"type":"string"},"doing":{"type":"string"}}}`

## `agent_heartbeat`

Mark an agent as alive now, optionally updating its doing line. The agent must be registered.

Input schema: `{"type":"object","properties":{"agent":{"type":"string"},"doing":{"type":"string"}}}`

## `agent_list`

List registered agents with seconds since each was last seen, whether it is active (seen within stale_after seconds, default 300), and the tasks it has claimed.

Input schema: `{"type":"object","properties":{"stale_after":{"type":"integer"}}}`

## `task_release_stale`

Find claimed tasks whose assignee is registered but has not been seen for more than stale_after seconds (default 300), so a crashed session does not hold them forever. Without release it only lists them; with release true it gives each back (status open) and adds a note saying why. Claims by agents that are not registered are listed under unregistered and never released, since there is no last_seen to judge them by.

Input schema: `{"type":"object","properties":{"stale_after":{"type":"integer"},"release":{"type":"boolean"},"agent":{"type":"string"}}}`

## `agent_unregister`

Remove an agent from the registry. Its claimed tasks stay claimed (release them first, or another agent can release with force).

Input schema: `{"type":"object","properties":{"agent":{"type":"string"}}}`

## `project_create`

Create a project (a named group of tasks; names are unique, at most 64 characters). Tasks join it with task_create or task_move.

Input schema: `{"type":"object","properties":{"name":{"type":"string"},"description":{"type":"string"}},"required":["name"]}`

## `project_list`

List projects, each with its milestones and counts of its tasks by status (milestone counts too).

## `project_rename`

Rename a project. Its milestones and tasks follow the new name (each task gets a history entry). The new name must be unused and at most 64 characters.

Input schema: `{"type":"object","properties":{"name":{"type":"string"},"new_name":{"type":"string"},"agent":{"type":"string"}},"required":["name","new_name"]}`

## `project_delete`

Delete a project and its milestones. Refused while any task is still in the project: move or finish those first.

Input schema: `{"type":"object","properties":{"name":{"type":"string"}},"required":["name"]}`

## `milestone_create`

Add a milestone to a project (names are unique within the project, at most 64 characters). Tasks join it with task_create or task_move.

Input schema: `{"type":"object","properties":{"project":{"type":"string"},"name":{"type":"string"},"description":{"type":"string"}},"required":["project","name"]}`

## `milestone_rename`

Rename a milestone within its project. Its tasks follow the new name (each task gets a history entry). The new name must be unused in that project and at most 64 characters.

Input schema: `{"type":"object","properties":{"project":{"type":"string"},"name":{"type":"string"},"new_name":{"type":"string"},"agent":{"type":"string"}},"required":["project","name","new_name"]}`

## `milestone_set_done`

Mark a milestone done (done true) or not done (done false); project_list reports it. This is a flag you set: it does not change its tasks, and creating or moving tasks into a done milestone is still allowed.

Input schema: `{"type":"object","properties":{"project":{"type":"string"},"name":{"type":"string"},"done":{"type":"boolean"}},"required":["project","name","done"]}`

## `milestone_delete`

Delete a milestone. Refused while any task is still in it: move those first.

Input schema: `{"type":"object","properties":{"project":{"type":"string"},"name":{"type":"string"}},"required":["project","name"]}`
